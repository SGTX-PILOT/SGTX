     1→etc.) is fully prepared to execute their first trade or service on the
     2→SGTX platform. The Trade Readiness Assessment evaluates company
     3→configuration, banking setup, trade preferences, security posture, and
     4→legal acknowledgements before allowing trade creation.

     7→

     9→advanced items). Each category contains several checklist items. For a

    12→not required.

   104→2.8.5 One‑Click Remediation Workflow
   105→
   106→For each missing item, the system provides a direct action link that:
   107→
   108→1.  Opens a pre‑filled form (where possible).
   109→
   110→2.  Guides the user through the required steps.
   111→
   112→3.  Upon completion, automatically updates the checklist status and
   113→    recalculates the readiness score.
   114→
   115→Example — Missing settlement account:
   116→
   117→-   User clicks Connect PSP.
   118→
   119→-   Modal appears with a list of available PSPs (Fawry, PayMob, CBE
   120→    IPN).
   121→
   122→-   User selects a PSP and is redirected to the PSP's OAuth flow.
   123→
   124→-   After successful linking, SGTX receives a webhook and marks the item
   125→    as completed.
   126→
   127→-   The Readiness Card updates instantly (score increases).
   128→
   129→2.8.6 Integration with Governor (Trade Creation Block)
   130→
   131→When a user attempts to create a new trade and their current readiness
   132→score is <70%, the Governor returns a CONDITIONAL verdict with a
   133→Decision Panel that:
   134→
   135→-   Lists the missing items.
   136→
   137→-   Provides direct action buttons for each missing item.
   138→
   139→-   Includes an "Ignore and Proceed" button only if the score is between
   140→    70% and 84% (with a warning log).
   141→
   142→-   For scores <70%, the "Proceed" button is disabled.

   416→2.10 SGTX Trade Trust Passport™
   417→
   418→2.10.1 Purpose
   419→
   420→Provide a portable, participant‑controlled institutional trust
   421→profile that aggregates a tenant's reliability, compliance, financing
   422→performance, dispute resolution, and verified identifiers. The Trust
   423→Passport is a verifiable credential (W3C standard) signed by SGTX,
   424→enabling participants to share their trustworthiness with
   425→counterparties, financiers, logistics providers, and regulators without
   426→exposing raw trade data.
   427→
   428→Key principles (non‑marketplace, sovereign):
   429→
   430→-   Participant‑controlled: No automatic sharing. Every share requires
   431→    explicit consent.
   432→
   433→-   Privacy‑preserving: Passport contains aggregated scores and
   434→    summaries, not transaction‑level details.
   435→
   436→-   Verifiable off‑line: Passport includes a cryptographic signature
   437→    that can be verified using SGTX's public key.
   438→
   439→-   Revocable: Sharing links can be revoked at any time; old links
   440→    become invalid immediately.
   441→
   442→-   No ranking or discovery: The Passport never suggests "better"
   443→    counterparties; it only reflects the tenant's own verified history.
   444→

   623→2.10.4 Sharing Workflow (One‑Click)
   624→
   625→Step 1 — Generate Passport:
   626→Tenant admin navigates to Company Admin → Trust Passport and
   627→clicks "Generate Passport" (one click).
   628→
   629→-   System creates a new verifiable credential.
   630→
   631→-   Passport is valid for 90 days (configurable per tenant).
   632→
   633→-   Admin sees a summary card with TRI, confidence, and expiration.
   634→
   635→Step 2 — Share with Counterparty:
   636→Admin clicks "Share Passport" → selects the recipient's GTID (from saved
   637→contacts) or chooses "Anyone with link" (anonymous token).
   638→
   639→-   If specific GTID, the system verifies that the recipient is an
   640→    existing counterparty.
   641→
   642→-   Admin selects which dimensions to share.
   643→
   644→-   Click "Generate Link" → system returns a one‑time token URL.
   645→
   646→-   Admin copies link and sends to recipient (outside SGTX).
   647→
   648→Step 3 — Recipient Verification:
   649→Recipient opens the link (no login required).
   650→
   651→-   Page displays the passport data (only the dimensions the sharer
   652→    consented to).
   653→
   654→-   Recipient can download signed JSON or copy a verification code to
   655→    check offline.
   656→
   657→-   The page shows a green checkmark if the signature is valid and the
   658→    passport is not revoked or expired.
   659→
   660→Step 4 — Revoke Access:
   661→At any time, admin clicks "Revoke" next to the shared token.
   662→
   663→-   Revocation is immediate.
   664→
   665→-   Any subsequent attempt to verify that token returns { "valid":
   666→    false, "reason": "revoked" }.
   667→
   668→One‑click guarantee: Generate Passport (1), Share (1), Revoke (1).
   669→
   670→2.10.5 Offline Verification & Public Key
   671→
   672→Any party can verify a Trust Passport offline using the SGTX public key.
   673→
   674→Steps (for recipient):
   675→
   676→1.  Download the signed passport JSON.
   677→
   678→2.  Use the open‑source tool trust-verify (provided by SGTX).
   679→
   680→3.  Verify signature and check that expires_at is in the future.
   681→
   682→Public keys are published
   683→at: https://sgtx.io/.well-known/sgtx-keys (Ed25519 and optional
   684→Dilithium3 for archival).
