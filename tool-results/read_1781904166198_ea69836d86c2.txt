   485→PART 14 — SECURITY & THREAT MODEL (STRIDE + MITRE ATT&CK)
   486→
   487→14.0 Purpose & Design Philosophy
   488→
   489→The SGTX platform handles sensitive trade data, financial transactions,
   490→and cryptographic identities across multiple jurisdictions. A robust
   491→security model is not optional — it is a constitutional requirement.
   492→This part defines the comprehensive threat model for the SGTX platform
   493→using industry‑standard frameworks:
   494→
   495→-   STRIDE (Spoofing, Tampering, Repudiation, Information Disclosure,
   496→    Denial of Service, Elevation of Privilege) — per component, per
   497→    trust boundary.
   498→
   499→-   MITRE ATT&CK — adversary tactics, techniques, and procedures (TTPs)
   500→    relevant to trade platforms.
   501→
   502→All mitigations are zero‑cost, built on open‑source tools (OPA,
   503→WasmEdge, Cilium, Falco, etc.) and free threat intelligence feeds. AI
   504→(Groq, Hugging Face) is used for advisory purposes — e.g., summarising
   505→threat findings, generating post‑mortems, and suggesting remediation
   506→steps. Never autonomous blocking (A5 forbidden).
   507→
   508→AI Integration in Part 14:
   509→
   510→  -----------------------------------------------------------------------
   511→  AI Level          Use Cases
   512→  ----------------- -----------------------------------------------------
   513→  A1 (Groq →        Summarisation of threat findings, post‑mortem
   514→  Ollama)           reports, incident notifications
   515→
   516→  A2 (HF local →    Threat intelligence feed parsing, anomaly detection,
   517→  Ollama)           log analysis
   518→
   519→  A4 (OPA +         Enforcement of security policies (RLS, mTLS, rate
   520→  WasmEdge)         limiting, constitutional rules)
   521→  -----------------------------------------------------------------------
   522→
   523→Key principles (non‑marketplace, orchestration‑only):
   524→
   525→-   Zero‑trust architecture — no implicit trust; every request is
   526→    authenticated, authorised, and encrypted.
   527→
   528→-   Defence in depth — multiple layers of control (network, application,
   529→    data, constitutional).
   530→
   531→-   Immutable audit — every security‑relevant event is logged immutably
   532→    via Loom.
   533→
   534→-   Continuous verification — hourly Loom chain verification, weekly
   535→    pentests, daily vulnerability scans.
   536→
   537→-   No security‑through‑obscurity — all security controls are documented
   538→    and verifiable.

   558→  analysis                                                     (automated)

   560→  4. MITRE ATT&CK Adversary tactics, techniques, and           Quarterly
   561→  mapping         procedures (TTPs) relevant to trade

   564→  5. Mitigation   Preventive, detective, corrective            On‑going
