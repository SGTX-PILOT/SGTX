## 1. USTN Lineage Report

USTN format (canonical, validated by `validateUSTNFormat` in `src/lib/sgtx/ustn/index.ts`):
`^SGTX-[A-Z0-9]{6}-[A-Z0-9]{6}-\d{14}-[A-HJ-NP-Z2-9]{8}$`
Generated by `generateUSTN(buyerGtid, sellerGtid)` using the last 6 chars of each GTID + ISO timestamp + 8-char random.

### 1.3 Alternate transaction identifiers

- `tradeId` (Prisma cuid) is used **in addition to** USTN on most routes. Most child records (Document, LabTest, QcInspection, CustomsDeclaration, Invoice, Activity, TimelineEvent) are linked by `tradeId`, not by USTN. This is a **lossy** representation because the `tradeId` is stable but the `ustn` field is replaced at contract lock — so any row written before lock carries the placeholder USTN.
- `orderId` is used in the Order screens (PurchaseOrders, SalesOrders) as `poNumber` / `soNumber` — those are separate models that ALSO carry a `ustn String?` column (per schema).
- `contractId` and `submissionId` are local to their tables; both carry an additional `ustn` column.

### 1.4 USTN lineage verdict

The USTN *exists* as a first-class canonical identifier and is propagated across most steps. The core integrity break is the **placeholder-replacement at contract lock that does NOT fan out** to rows written before lock. Result: `ServiceQuotation.ustn`, `BuyerSubmission.ustn`, and any pre-lock `Dispute.ustn` retain the `SGTX-PEND-...` placeholder, not the minted USTN. Reads by USTN against those tables return stale results.

## 2. TCC (Trade Context Continuity) Verdict

The Trade Command Center (`src/components/sgtx/TradeCommandCenter.tsx`) is the full-screen overlay shown when `view === "tcc" && activeUstn` (`src/app/page.tsx` line 61). It derives its entire context from:

```ts
const ustn = useAppStore((s) => s.activeUstn);
const { data: trade } = useQuery({
  queryKey: ["tcc", ustn],
  queryFn: () => (await fetch(`/api/sgtx/trade?ustn=${ustn}`)).json(),
  enabled: !!ustn,
});
```

The `/api/sgtx/trade?ustn=...` route (`src/app/api/sgtx/trade/route.ts`) returns the full Trade row + nested shipments, containers, documents, activities, invoices, labTests, qcInspections, customsDecls, financing (with bids), disputes, quotations, timeline, chatMessages. It is **USTN-keyed and tenant-isolated** (IDOR check at lines 57-82). TCC itself does NOT special-case by portal — all 12 portals see the **same** canonical trade context for the same USTN.

`ActiveTradeContextBar` (`src/components/sgtx/ActiveTradeContextBar.tsx`) is the persistent chip in `WorkspaceShell` that lets the user pick the active USTN context (store field `activeUstnContext`). It calls `/api/sgtx/trade?ustn=...` and shows status, phase, commodity, incoterm, health, pending action.

### TCC continuity verdict — **partial continuity**

- ✅ All 12 portals route through `useAppStore((s) => s.activeUstn)` / `activeUstnContext` for the TCC overlay and the context bar.
- ✅ `/api/sgtx/trade?ustn=...` is the canonical single-USTN lookup. Same response shape across portals.
- ❌ **Workspace content components do NOT consume `activeUstnContext`**. Spot-checking `src/components/portals/PortalContent.tsx`:
  - Contract signing screen uses a local `selectedUstn` derived from `readyTrades` (line 6493), **not** the global store. Falls back to `FALLBACK_TRADE_USTN` (line 6475, hardcoded).
  - Distressed Cargo screen uses local `useState("SGTX-1397F3A-...")` (line 7513).
  - Lifecycle screens (NegotiationsScreen, PurchaseOrdersScreen, SalesOrdersScreen, ProformaInvoicesScreen, RegulatorySnapshotsScreen) call `/api/sgtx/negotiation?ustn=${tenantGtid}` (line 46) — passing the **tenant GTID as the USTN**, which is semantically wrong. The API may tolerate it but the contract is broken.
  - OneClickCloseUstn (line 9491) takes `trades[0].ustn` from dashboard data — not the active context.
- ❌ `WorkspaceShell.tsx` reads `activeUstnContext` but only renders it as a text chip (line 699-702). It does NOT thread the active USTN down to the workspace content components.

**Result:** The TCC overlay itself is USTN-canonical. The Active Trade Context Bar is a visible chip that the user can set. But individual workspace content (Contract Signing, Distressed, Lifecycle, One-Click Close) ignores the global context and uses local component state — sometimes hardcoded, sometimes the first item from a dashboard list. The blueprint's "single USTN view across portals" promise is honored at the overlay layer only.

## 3. State Vector / Multi-Clock Integrity

The blueprint requires 4 clocks (Execution / Financial / Legal / Physical-Operational). The implementation in `src/lib/sgtx/state-vector/index.ts` actually goes further — it defines **12 state domains**:

`execution, financial, legal, physicalOperational, documentary, compliance, regulatory, counterparty, reconciliation, dispute, exposure, closure`

with finality classes F0..F5, divergence index NONE/LOW/MEDIUM/HIGH/CRITICAL, transaction health GREEN/YELLOW/ORANGE/RED/BLACK, and a 0..1 state integrity score. Pure compute helpers (`computeDivergenceIndex`, `computeTransactionHealth`, `computeStateIntegrity`, `computeFinalityClass`) are deterministic and well-tested.

`getOrCreateStateVector(ustn)` / `updateStateDomain(ustn, domain, value)` / `getStateVector(ustn)` are wired to a `TransactionStateVector` Prisma model (one row per USTN, unique constraint on `ustn`).

### 3.1 Where the system is lossy

The state-vector lib is **imported by only 8 files**:

```
src/lib/sgtx/state-vector/index.ts          (the lib itself)
src/lib/sgtx/closure-policy/index.ts         (reads state vector for closure evaluation)
src/lib/sgtx/dispute-packet/index.ts         (reads state vector for dispute packet)
src/lib/sgtx/event-spine/index.ts            (event spine references)
src/lib/sgtx/governor/gates-constitutional.ts (G-A1 gate — see §5)
src/middleware.ts                             (one reference)
src/app/api/sgtx/constitutional/state-vector/route.ts      (GET / POST state vector)
src/app/api/sgtx/constitutional/state-vector/update/route.ts (POST update domain)
```

Notably **ABSENT from** the list of callers (verified by grep for `from "@/lib/sgtx/state-vector"` and `updateStateDomain|getStateVector|getOrCreateStateVector`):

- `src/app/api/sgtx/trade-request/route.ts` — does NOT call `getOrCreateStateVector` when creating a Trade.
- `src/app/api/sgtx/contract/lock/route.ts` — does NOT update `execution`/`legal` domains when USTN is minted.
- `src/app/api/sgtx/quote/submit/route.ts` — does NOT update the `legal` domain when quote is submitted.
- `src/app/api/sgtx/quote/accept/route.ts` — does NOT update the `legal` domain when quote is accepted.
- `src/app/api/sgtx/contract/sign/route.ts` — does NOT update `legal` domain when contract is signed.
- `src/app/api/sgtx/milestone/confirm/route.ts` — does NOT update `execution` / `physicalOperational` domains on each milestone.
- `src/app/api/sgtx/payment/pay/route.ts` and `/api/sgtx/payment/stage1/route.ts` — do NOT update `financial` domain on payment.
- `src/app/api/sgtx/settlement/approve/route.ts` — does NOT update `financial` / `reconciliation` domains.
- `src/app/api/sgtx/customs-declaration/generate/route.ts` — does NOT update `regulatory` / `compliance` domains.
- `src/app/api/sgtx/qc-inspections/*` — do NOT update `documentary` / `compliance` domains.
- `src/app/api/sgtx/ustn-close/route.ts` — calls `closeTrade` which updates `TradeClosureState`, but does NOT update the state vector's `closure` domain via `updateStateDomain`.

### 3.2 Single-status collapse (lossy)

In the absence of state-vector updates, the UI and most APIs collapse the trade reality to a **single `Trade.status` string** (`INITIATED, PENDING_SELLER_RESPONSE, QUOTED, QUOTE_ACCEPTED, BUYER_SUBMITTED, CONTRACT_SIGNED, IN_EXECUTION, DELIVERED, SETTLED, COMPLETED, DISPUTED, DISTRESSED, CANCELLED`). This is the column the dashboard, TCC, Active Trade Context Bar, and LifecycleScreens all read. The 12-dimensional state vector exists in the schema and the lib but is **not fed by mutations**, so it stays at the F0 / PENDING defaults forever.

### 3.3 State vector findings

- ✅ The 12-domain model is implemented correctly per blueprint §6-§8.
- ✅ Pure compute helpers (divergence, health, integrity, finality) are deterministic and correct.
- ✅ A Prisma model `TransactionStateVector` with a unique constraint on `ustn` exists.
- ❌ **The state vector is not fed by lifecycle mutations.** No API route between trade creation and USTN close calls `updateStateDomain`. The vector is effectively a parallel construct that the closure engine reads — but it always sees the default F0 / PENDING / OPEN values.
- ❌ UI collapses reality to the single `Trade.status` string. TCC and Active Trade Context Bar do not visualize the 12-domain vector.
- ⚠️ `src/app/api/sgtx/constitutional/state-vector/update/route.ts` is the only write path. It is a **manual** endpoint — no automatic lifecycle hook updates the vector. Calling it requires out-of-band admin action.

## 4. Lifecycle Coverage

The blueprint specifies a 12-stage lifecycle:
`INTENT → AGREEMENT → OBLIGATION_CREATION → PRE_EXECUTION_VALIDATION → EXECUTION → VERIFICATION → PROVISIONAL_SETTLEMENT → FINANCIAL_CONFIRMATION → RECONCILIATION → FINALIZATION → POST_CLOSURE_OBSERVATION → CLOSED`
plus side paths: `DISPUTE, REVERSAL, CORRECTION, LEGAL_REVIEW`.

The implementation in `src/lib/sgtx/ustn/index.ts` defines **16 USTN statuses** (lines 33-50): `INITIATED, STAGE1_PENDING, STAGE1_SETTLED, CUSTOMS_SUBMITTED, BOOKED, LOADED, DEPARTED, IN_TRANSIT, ARRIVED, CUSTOMS_IMPORT, DELIVERED, SETTLED, COMPLETED, DISPUTED, DISTRESSED, CANCELLED` and the transition map `USTN_TRANSITIONS` (lines 700-717). The comment on lines 696 and 719 labels these as "STUB" — but the transition table is functionally complete.

The `USTN_TRANSITIONS` table does **not** include the blueprint's stages: `INTENT, AGREEMENT, OBLIGATION_CREATION, PRE_EXECUTION_VALIDATION, VERIFICATION, PROVISIONAL_SETTLEMENT, FINANCIAL_CONFIRMATION, RECONCILIATION, FINALIZATION, POST_CLOSURE_OBSERVATION`. It also has **no side-path transitions** for `REVERSAL, CORRECTION, LEGAL_REVIEW`. The only side paths are `DISPUTED` and `DISTRESSED`.

A separate closure state machine in `src/lib/sgtx/trade-closure/index.ts` and `TradeClosureState` Prisma model implements: `OPEN → READY_FOR_CLOSURE → USTN_CLOSED` (or `USTN_CLOSED_WITH_OPEN_DISPUTE`) with `reopenTrade` reverting `USTN_CLOSED → OPEN`.

### 4.2 Lifecycle coverage summary

- ✅ Precondition checks: implemented on all write paths (idempotency, status gates, atomic transactions, sequence chains).
- ❌ Authorization (Governor): called on 6 of 14 transitions (trade-request, contract/sign, payment/pay, settlement/approve, disputes/file, financing/disburse). **Missing** on quote/submit, quote/accept, contract/lock, milestone/confirm, customs-declaration/generate, ustn-close, reopen. Even when called, the Governor is invoked with `{action, actorGtid}` only — no `traderMode`, no `actorRole`, no `payload` — so `opaEvaluate` and `dualModeGate` silently return ALLOW (see §5).
- ❌ Canonical event emission (`appendEvent` from event-spine): only on **ustn-close**. All other transitions rely on the Brain OS `eventBus.publish` (a separate system) and on `Activity` log rows. The blueprint's "canonical event spine hash chain" is empty for most transitions.
- ✅ Audit records: every transition creates an `Activity` row. Contract lock + sign also write `TimelineEvent`. USTN close writes `TradeClosureState`.
- ✅ Notifications (Smart Inbox): present on most transitions. **Missing** on USTN close and reopen — parties are not notified when the trade is closed or reopened.
- ❌ Side paths: `REVERSAL`, `CORRECTION`, `LEGAL_REVIEW` are **not implemented** in the USTN_TRANSITIONS table. `DISPUTE` is implemented (and reverses FeeLock + auto-revokes release authorisations). `reopenTrade` is a state reverter but is not labeled as REVERSAL.
- ❌ Blueprint stages `INTENT, AGREEMENT, OBLIGATION_CREATION, PRE_EXECUTION_VALIDATION, VERIFICATION, PROVISIONAL_SETTLEMENT, FINANCIAL_CONFIRMATION, RECONCILIATION, FINALIZATION, POST_CLOSURE_OBSERVATION` are not modeled as distinct lifecycle states. The implementation collapses them into the 16 shipment-and-financial statuses above.

Each file's header explicitly says: *"Simulated by src/lib/sgtx/governor/policies.ts (opaEvaluate)."* — confirming the on-disk Rego is **not loaded into the running application**.

### 6.2 Rego content in code

`src/lib/sgtx/governor/policies.ts` exports an `OPA_POLICIES` array that holds each policy's `.rego` source as a string. This is used by:
- `src/app/api/sgtx/opa/policies/route.ts` (GET /api/sgtx/opa/policies — list)
- `src/app/api/sgtx/opa/policies/[name]/route.ts` (GET / PUT — read/update a policy)

These endpoints **read and update the Rego source as a string** (with multisig approval + audit log), but they do NOT compile or evaluate the Rego. The `PUT` endpoint validates that the new content starts with `package sgtx.` and persists it to the `OpaPolicy` Prisma table.

### 6.3 Actual OPA evaluation in the Governor

`src/lib/sgtx/governor/index.ts:231-275` defines `opaEvaluate(input)` — a TypeScript function that **mimics** parts of the Rego logic but is not a Rego interpreter:

- Checks `input.actorRole` against a hardcoded `actionPerms` table (lines 234-241). Same as `permissions.rego` `permissions := {...}` block but with FEWER actions (no `quote.submit`, `quote.accept`, `compliance.review`, `reserve.attest`).
- Checks `input.readinessScore >= 70` for `trade.create` (matches Rego).
- Checks `input.reserveRatio < 1.1` for reserve actions (matches `reserve.rego`).
- Checks `input.quarterlyAttestation === false` for reserve actions (matches `reserve.rego`).

Missing from the TS simulation but present in Rego:
- `dual_mode_gate` enforcement in `permissions.rego` (lines 110-119) — the Rego denies BUY mode for `quote.submit, exw.lock, packing.lock, logistics.addenda.sign`. The TS `opaEvaluate` does not check trader mode at all.
- `can_read_trade` data scope rules (lines 73-88 of permissions.rego) — not implemented in `opaEvaluate`.
- `view.recommended.counterparties` forbidden deny (lines 93-96 of permissions.rego) — not implemented in `opaEvaluate`.
- `deny[msg]` for insufficient role (lines 101-104) — `opaEvaluate` returns a single condition, not Rego's deny-list.
- DUAL-mode + KYB tier check (lines 36-41) — not in `opaEvaluate`.

### 6.4 OPA verdict

- ❌ Rego files on disk are **not loaded** by the running application.
- ⚠️ Rego source is stored as a string in TS / DB for display + multisig update, but never parsed or evaluated.
- ⚠️ The TS `opaEvaluate` is a partial mirror of `permissions.rego` + `reserve.rego` only. The other 6 Rego files (`fee, financing, distressed, multiship, logistics, broker`) have no TS counterpart at all — even partial.
- ❌ OPA is **stubbed**. The blueprint's "OPA (Rego) policy evaluation" requirement is not met in production.

## 7. WasmEdge Findings

### 7.1 Wasm module "registry"

`src/lib/sgtx/governor/wasm-modules.ts` declares 7 "wasm modules" (`constitutional_rules.wasm, jurisdiction_matrix.wasm, incoterms_engine.wasm, fee_gate.wasm, dual_mode_gate.wasm, reserve_rules.wasm, distressed_country_gate.wasm`). Each entry has:
- name, version (semver string), hash (derived as `sha256("sgtx-" + name + "-" + version)`)
- signedBy, loadedAt, status, description, sizeBytes, history[]

The registry is in-memory only (line 171). `verifyModuleSignature(name, hash)` simulates Ed25519 signature verification by re-deriving a SHA256 hash from `name|hash|signedBy|salt` and comparing — **not** a real signature check (line 226).

`reloadModule(name, opts)` simulates the 8-step hot-reload procedure (NATS publish → download → verify → quiesce → swap → Loom-anchor → resume) entirely in TypeScript with `setTimeout(50)` as the "quiesce drain" step. The actual "bundle" is just `sha256("sgtx-<name>-<newVersion>")` — there is no wasm bytecode.

### 7.2 WasmEdge execution in the Governor

`src/lib/sgtx/governor/index.ts` lines 75-227 implement the 7 "wasm" modules as TypeScript functions: `constitutionalRules`, `jurisdictionMatrix`, `incotermsEngine`, `feeGate`, `dualModeGate`, `reserveRules`, `distressedCountryGate`. The header comment at line 75 explicitly says *"Part 1.3 WasmEdge simulation"*. Each function:

- Returns `{ verdict, conditions }`.
- Implements the constitutional rule in pure TypeScript.
- Has no WasmEdge runtime dependency, no `.wasm` file, no bytecode.

The 8 "modules" (7 wasm + 1 OPA) are dispatched in parallel in `governorDecide` (lines 433-441) with a 50 ms hard timeout. Module versions are recorded in `MODULE_VERSIONS` (lines 78-86).

### 7.3 WasmEdge verdict

- ❌ WasmEdge / Wasm runtime is **not loaded**. There is no `.wasm` file, no WasmEdge process, no bytecode compilation.
- ❌ "Wasm modules" are TypeScript functions in `governor/index.ts`. The "module registry" in `wasm-modules.ts` is a metadata simulator with synthetic hashes derived from strings.
- ❌ Hot-reload is a 50 ms `setTimeout` simulation that swaps an in-memory record. No actual code is hot-swapped.
- ❌ Signature verification is `sha256(name + hash + signer + salt)` string equality — not Ed25519.
- ⚠️ The TS simulations do implement the **logic** of the constitutional rules (fee bounds, A5 prohibition, jurisdiction tiers, dual mode, reserve composition, distressed country factors) — so the *business rules* are enforced, just not in a sandboxed wasm runtime.

### Overall risk: **MEDIUM-HIGH**

The platform has the **shapes** of all blueprint requirements (USTN, TCC, state vector, lifecycle, Governor, OPA, WasmEdge, event-spine, Loom chain) implemented in code, but several are **partially or fully stubbed**:

1. **State vector** is a parallel construct that mutations don't feed — it's effectively dead code in production. The UI uses the lossy single-status model.
2. **Governor** is called but under-fed — most mutations either skip it entirely or pass only `{action, actorGtid}`, causing OPA RBAC and dual-mode gates to silently ALLOW.
3. **OPA (Rego)** is on-disk documentation only. The runtime uses a TS function that mirrors a subset of `permissions.rego` + `reserve.rego`. The other 6 Rego files have no runtime equivalent.
4. **WasmEdge** is entirely simulated as TypeScript functions. No wasm bytecode, no runtime, no real Ed25519 signature verification.
5. **Canonical event emission** is wired only on `ustn-close`. The lifecycle's hash chain has gaps for every other transition.
6. **Constitutional gates (G-A1..G-A7)** are defined but not called by any mutation.
7. **USTN fan-out at contract lock** is incomplete — pre-lock child rows keep the placeholder `SGTX-PEND-...` USTN.
8. **Workspace content** ignores the global active USTN context and uses local state / hardcoded fallbacks.

### Recommended next actions (in priority order)

1. **Wire `updateStateDomain` calls into every lifecycle mutation** (trade-request, quote/submit, quote/accept, contract/sign, contract/lock, milestone/confirm, payment/*, settlement/approve, customs/*, qc/*, ustn-close, reopen). Without this, the state vector stays at F0 forever and the closure engine reads defaults.
2. **Pass `traderMode` + `actorRole` + `payload` to `governorDecide`** in contract/sign, payment/pay, settlement/approve, disputes/file. Without these fields, OPA RBAC and `dual_mode_gate` silently ALLOW.
3. **Add Governor calls** to quote/submit, quote/accept, contract/lock, milestone/confirm, customs-declaration/generate, ustn-close, reopen.
4. **Add `appendEvent` calls** to every transition (contract lock, quote submit/accept, contract sign, milestone confirm, payment, settlement, customs, dispute file, distressed declare, reopen). Currently only `ustn-close` emits a canonical event.
5. **Fan-out USTN replacement at contract lock** — update `ServiceQuotation.ustn`, `BuyerSubmission.ustn`, `Dispute.ustn` when `Trade.ustn` is minted. (Or: stop writing the placeholder and write `null` until lock.)
6. **Thread `activeUstnContext`** into workspace content components as a prop, replacing local `selectedUstn` / `FALLBACK_TRADE_USTN` defaults.
7. **Wire G-A1..G-A7 constitutional gates** into the closure flow (`evaluateClosureReadiness` should consult `mergeConstitutionalGates`).
8. **Replace hardcoded `SGTX-1397F3A-...`** in `payment-orchestration-screens.tsx` with the active USTN context. Fix the malformed `FIXTURE_USTN` in `completion-screens.tsx` (5-char `DEBUY`).
9. **Implement a real OPA evaluator** (e.g. `@open-policy-agent/opa-wasm` or a server-side OPA bundle loader) that compiles and runs the Rego source in `core/governor/policies/*.rego`. The current TS simulation drifts from the Rego.
10. **Either load WasmEdge** (real `.wasm` modules compiled from Rust) or **remove the "WasmEdge" branding** and document the gates as TypeScript functions. The current state where the code claims to load 7 wasm modules but actually runs TS functions is misleading.
11. **Add notifications** (Smart Inbox) to `ustn-close` and `reopenTrade` — parties are not notified when the trade is closed or reopened.
12. **Add REVERSAL / CORRECTION / LEGAL_REVIEW side paths** to `USTN_TRANSITIONS` if the blueprint requires them.
